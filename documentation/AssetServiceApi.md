# AssetServerApi

## Deployment
The asset server is deployed with the Specify-Adapter.
There is a full local setup in docker-compose-specify.yaml (read README.md -> How to run Specify locally)

For Specify to work:
* In Specify change the ASSET_SERVER_URL to point at the Specify-Adapter
* In Specify-Adapter mirror Specify ASSET_SERVER_KEY to SPECIFY_WEB_ASSET_SERVICE_TOKEN_KEY

## ENV Configurations
### `SPECIFY_WEB_ASSET_SERVICE_ALLOW_STATIC_FILE_ACCESS`

This controls if the `/static/{path}` endpoint can be used.

If true, files can be opened directly by URL.
If false, `/static/{path}` returns `404`.

### `SPECIFY_WEB_ASSET_SERVICE_FILE_FRIENDLY_POSTFIX`

File path postfix that is added on when trying to upload and download files from the parking space

### `SPECIFY_WEB_ASSET_SERVICE_TOKEN_KEY`

The token KEY Specify uses to generate their tokens.
In Specify the ENV variable is called ASSET_SERVER_KEY
The token key is used to validate that the token has been created by Specify

### `SPECIFY_WEB_ASSET_SERVICE_TOKEN_TIME_TOLERANCE_SECONDS`

Token lifetime in seconds 

### `SPECIFY_WEB_ASSET_SERVICE_TOKEN_REQUIRED_FOR_GET`
Controls if GET endpoints should validate the token or ignore it

### `SPECIFY_WEB_ASSET_SERVICE_INSTITUTION`

This config exists in the asset server config, but it is not really used by `AssetServerApi.java` itself.

## Token
The token is generated by Specify and the key used in the token generation is given by ASSET_SERVER_KEY ENV

## Endpoints

### `GET /`

Endpoint to test that the API can be reached.

Returns:

- `200 OK` with `It works!`

### `GET /static/{path}`

Returns a static file if static file access is turned on.

In simple terms, this is used to open a file directly by URL.

Returns:

- `200 OK` with the file content
- `404` if static file access is turned off
- `404` if the path is not valid
- Error from fileproxy

### `GET /getfileref`

Returns a URL for a file.
Returns:

- `200 OK` with a text URL
- Error from fileproxy

### `GET /fileget`

Returns a file.

Returns:

- `200 OK` with the file content
- `403` if token validation fails
- Error from fileproxy

### `OPTIONS /fileupload`

Preflight to check CORS.
Returns:
- `200 OK`
- CORS error

### `POST /fileupload`

Uploads a file.
Validates the token.
Thumbnails are ignored.
Validates Collection.

Returns:

- `200 OK` with `Ok.` when upload worked
- `200 OK` with `Ignoring thumbnail upload!` when the file type is a thumbnail
- `400 Bad Request` if no file was sent
- `404 Not Found` if the collection is unknown
- Error from fileproxy

### `POST /filedelete`

Deletes a file.
Returns:

- `200 OK` with `Ok.` if the delete worked
- Error from fileproxy

### `GET /getmetadata`

Reads metadata from a file.
If `dt=date` it will look for EXIF DateTimeOriginal.
If `dt=date` is not used, it returns a JSON list of metadata entries.

Returns:

- `200 OK` with metadata as JSON
- `200 OK` with the EXIF date as plain text when `dt=date` works
- `404` if `dt=date` is used but the EXIF date is not found
- `403` if token validation fails
- Error from fileproxy

### `GET /testkey`

Checks whether token validation is working and configured correctly.

Returns:

- `200 OK` with `Ok.` if the token is accepted
- `403` if token validation fails

### `GET /web_asset_store.xml`

Returns an XML file that tells Specify which endpoints to use for reading, uploading, deleting, and metadata.
Returns:

- `200 OK` with an XML document
